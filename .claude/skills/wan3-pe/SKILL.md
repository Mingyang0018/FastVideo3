# Wan 3.0 prompt优化

## 技能定位

本 Skill 把用户写下的文字请求连同图片、视频、音频素材引用，梳理成一条干净、结构化的视频生成请求。成品固定为【核心任务】【情节概要】【音频风格】【运镜与核心约束】【负面提示词】五段：用户的核心意图照搬不动，素材参考统一落在【核心任务】，主体映射顺着情节节点自然带出。

这一环节的性质是"格式化整理"，边界如下：

- 只梳理用户已经写出的剧情、主体、台词与参考诉求；不替用户扩写剧情，不加入用户没提过的内容。
- 产物会流向下游的提示词增强（PE）环节继续加工；本环节只把输入理清楚，生成阶段专用的表达交给后续环节完成。
- 素材全程只读：不改动原始素材，也不额外制作辅助素材。
- 任何情况下都不亲自调用视频生成接口；用户提出生成视频时，先给出整理后的请求，再移交后续流程。

## 触发与不触发

判断依据只看目标产物：把素材当作条件去生成一条新视频时启用本 Skill；产物必须直接改动输入视频原有时间线时不启用。输入里根本没有视频时，一律启用本 Skill。

应当加载本 Skill 的情形：

- 用户给出图片、视频、音频素材引用，希望整理或规范化成视频生成请求。
- 用户想参照素材里的人物、物体、场景、构图、光影、风格、动作、运镜、剪辑、特效或声音来生成新视频。
- 用户想把图片用作起始、过程或收尾的画面节点，或把完整视频、音频区间嵌进成片。
- 用户想在参考视频之前、之后或两段素材之间生成并衔接新内容。
- 用户只给了简略想法、长段描述或未经整理的复杂请求，需要梳理成能直接用的结构化请求。

不启用本 Skill 的情形：

- 剧情重塑类：用户点名要"重塑、颠覆、改编、重混、二次创作、重新演绎、翻拍"输入视频的既有剧情。这归剧情重塑任务，应向用户说明需要走对应的重塑流程。
- 直接编辑输入视频文件类：删除、替换、修复原视频里已有的画面、声音或时间线对象。这类请求把用户指令原样转交下游即可，无需整理。
- 只是了解接口参数、价格、配额、报错或模型能力。

## 硬性约束

1. **忠实原文**：人物身份与数量、关键道具、场景、事件因果、空间关系、故事结局一律照用户原文，不增删、不篡改。
2. **事实与观察分离**：身份、年龄、关系、事件与结局以用户文字为准；素材只补充能直接看到或听到的属性，观察到的表象不升格成剧情事实。
3. **主体基数匹配**：一张单人设定图只对应一个人物；有多个单人候选时先按一人一图分配，有多个群体候选时先按一组一图分配。只有同一主体的多视角、或素材画面本身就含同一群体时，才合并参考。
4. **用户映射优先**：用户点名指定的素材职责、主体名称与相互关系照搬不动。用户映射已经覆盖某个职责时，不再为同一职责补进没点名的素材。
5. **素材逐份负责**：每一份真正用到的素材，都写清采用它的什么、参考范围到哪里。
6. **结构化重组**：无论原请求是否完整，都要进对应模板重新组织；除了同义改写之外，做的是结构化梳理。
7. **参数分离**：画幅、总时长、分辨率、帧率交给页面或接口设置，只用来规划事件密度，不写进请求正文。用户自己写出的事件时间段属于创作内容，原样保留。
8. **不滥加约束**：只整理用户提出的要求；用户没要的画质包、水印、Logo、字幕或其他通用负向约束一律省略。
9. **只交付请求正文**：整条回复就是请求正文本身；开场确认、结尾总结、分析过程、整理说明与改动理由都留在内部整理阶段，不外露。
10. **单一最佳版本**：默认只给一条整理后的请求；用户明确要对比版本时才输出多条。
11. **最少澄清**：凡是能从文字、素材和上下文合理判断的，直接做完；只有当某个问题会改变核心结果、又存在多个等价解释时，才把疑问合并成一次发问。

## 素材输入情形

先分清输入落在哪一种情形，再动手整理。

### 无素材的纯文字请求

用户没有任何素材，文字里也没流露参考诉求。直接抽取主体、事件、场景、镜头与声音套基础模板；不编造素材编号，也不劝用户补素材。

### 引用素材但当前不可得

用户请求里已经写出的素材引用一律原样留住，含 `图N`、`视频N`、`音频N` 或运行环境里的等价标签。当前消息没带上对应素材、或当前环境读不到，都不是删除、改号或改写成无参考请求的理由。

照常按用户文字整理请求，保住素材职责与引用关系；不谎称已经看过素材，也不补写只有看过素材才能确认的细节。用户没写素材引用时，就不新增。素材读不到只限制"能确认哪些事实"，不因此卡住整理。

### 素材可读时

主动读取用户给的图片、视频、音频。先轻量过一遍全部素材，再结合请求建映射；不要仅凭文件名去猜素材内容。

### 数量与上限

素材偏多时提醒用户留意提交上限；仍在合理范围内就继续整理，靠逐份职责和按场景激活来压低素材间的相互干扰。确实要缩减时，先给出完整请求，再在正文后追加一行 `素材提示：`，说明提交前需要减掉哪些素材。

### 编号规则

本次上传的图片、视频、音频各自按上传顺序在模态内编号：图1、图2、视频1、音频1。编号只用来标识素材，跟它在成片里出现的先后无关。用户原始请求里的编号与引用形式全程保真。

## 整理流程

### 第一步：锁定故事合同

先据用户文字立一份"故事合同"，再回头核对素材引用。逐项抽取并锁定：

- 出场主体及其数量。
- 动作、事件与因果先后。
- 场景、时间、天气与空间方位。
- 道具的归属、交接与结局状态。
- 镜头、声音、台词与字幕诉求。
- 镜头时间戳：用户写了多少就保留多少。
- 用户点名要保留或排除的内容。

故事合同是整理时的事实边界：成品里每个事件、主体、台词都要能在用户原文里找到出处，不因为素材里有更抢眼的内容就替换或合并。

只要输入涉及说话、对白或旁白，就逐条记下说话人、台词原文、语言以及画内或画外位置。用户给的台词片段逐字照留；用户只描述了说话意图、没给原文时，保留那段意图描述，不自己编对白。

把每个明确露面的人物、群体、关键道具和场景登记进内部的"必需实体清单"；整理收尾前逐个确认它们都已进入请求。

用户请求里的"换成、替代"这类词是在描述参考关系（比如让图1的人物去做视频1里的动作）。整理时改说成"谁在做什么"，把人物与动作、场景等参考之间的对应关系写清楚。

### 第二步：读懂素材

素材偏多时分两遍来看：

1. 头一遍轻量扫过全部素材，圈出人物、商品、道具、场景、动作、运镜、声音与风格方面的候选。
2. 第二遍只细看那些与剧情对得上、彼此有冲突、或要当关键画面的素材。

看视频至少确认主体、主要动作、镜头变化和首尾状态；听音频至少确认声音类型、音色、语言、台词内容或环境声用途。

把信息分成两类来对待：

- **故事分配**：人物叫什么、年龄与关系、担哪个事件、道具归谁、结局怎样——这些一律来自用户文字。
- **可观察特征**：五官、发型、服装、颜色、材质、空间布局、动作、运镜、音色等能直接看到或听到的表象。

素材只用来补充能直接观察到的特征；无从确认的品牌、职业、性格、道具功能一概不补写。用户只叫"人物"或"主体"时，就沿用这个中性称呼；用户已经给了角色名或身份，才跟着用那个称谓。

映射打架时，按下面的优先级从高到低取舍：

1. 用户明确指定；
2. 请求正文里的描述；
3. 素材自身内容；
4. 文件名与元数据；
5. 上传顺序。

用户明确映射已经覆盖全部必需实体时，没被点名的其余可用素材默认不参与本次任务。

### 第三步：分配素材职责

每份被用到的素材只担一个明确职责：

- 图片：人物外貌与服装、商品结构与材质、道具、场景布局、光线，或某个画面节点。
- 视频：动作、运镜、节奏、时间线，或作为完整画面区间进入成片。
- 音频：说话人的音色与台词、环境声、音效或音乐，或作为完整声音区间进入成片。

建映射按这个顺序走：

1. 从必需实体清单里逐个取出还没分配的角色、群体、道具和场景。
2. 通览全部素材候选，比对人数、服装层级、轮廓、结构与职责匹配度；找到第一份能用的素材后仍要继续看其余候选。
3. 给当前槽位挑最匹配的素材，再处理下一个槽位。不同的已命名角色默认各用各的最佳候选。
4. 收尾做一次遗漏审计：每个必需实体恰好担一个明确职责，每份被用素材只担已声明的职责。

成品里的素材参考写法，一处只界定一个主体、道具或场景连同它的参考素材与采用范围；涉及多个主体就拆成多处分别绑定，例如：

```text
人物A对应图1，采用五官、发型和服装。
人物B对应图2，采用五官、发型和服装。
道具A对应图3，采用结构、材质和颜色。
场景A参考图4，采用空间布局、建筑和光线，图中人物保持忽略。
```

同一主体有多份参考时，分别讲清每份素材补的是哪个视角或属性，并声明它们共同界定同一个实体、只生成一个实例。

两份参考冲突时，先听用户指定；用户没指定就按清晰度和剧情匹配度来分；只有连核心身份都判不了时，才合并成一次发问。

### 第四步：把握映射确定性

按确定程度分档处理，档位与应对如下：

| 确定程度 | 应对 |
|---|---|
| 明确 | 直接映射，往下走。 |
| 可推断 | 采用最合理的映射继续整理，相关假设顺着正文对应内容自然体现，不单独声明。 |
| 存疑但不影响结果 | 该素材保持不采用，也不打扰用户。 |
| 存疑且影响核心 | 当歧义牵涉核心身份、数量、道具归属、空间关系或关键画面职责时，把疑点合并成一个简短问题，等回答后再给请求。 |

风格、光线、普通运镜，以及其他能靠上下文保守定夺的缺失项，都不用中断用户。

### 第五步：落模板并净化

挑下文对应的模板，只留当前任务需要的段落。所有占位内容都换成具体信息，模板自带的说明文字不出现在成品里。收尾先过一遍"交付前核对"，再按"交付约定"给出。

## 请求模板

### 五段请求结构

```text
【核心任务】
生成一段<题材或类型>的<视频内容概述>，参考<视频N/图N/音频N>中<主体或内容>的<形象/动作/场景/音色等采用内容>。全片采用<全局风格基调>。
素材参考在此集中写明；音色参考写为"<角色>的音色参考音频N"。

【情节概要】
1. <情节节点一：人物、动作、事件；用户台词逐字保留并绑定说话人>。
2. <情节节点二……>；使用音频N的音色说："<逐字原文>"。
<音色参考在对应说话节点写明。>
<用户为镜头写了时间戳时，对应节点以"镜头N xx-xx秒"开头，时间按用户原文逐字保留；用户未写时间戳时保持纯节点编号。>

【音频风格】
<对白语言与质感、现场音效、配乐的情绪与节奏走向。>
<用户未提及时保持一句简短概括或整段省略。>

【运镜与核心约束】
<镜头风格、运动方式、剪辑节奏，以及用户给出的硬性约束。>
<用户未提及时保持一句简短概括或整段省略。>

【负面提示词】
<逗号分隔的用户明确排除项。仅当用户明确要求排除某些内容时输出本段。>
```

段落取舍规则：【核心任务】和【情节概要】永远输出；【音频风格】【运镜与核心约束】看用户输入的详略来给，用户没提就写简短一句或整段省掉；【负面提示词】只有用户要求排除某些内容时才出现。简单任务可以只留核心两段。

填写示例（简单任务，音频与运镜用户未提及）：

```text
【核心任务】
生成一段修复旧木椅的手工记录视频，参考图1中木工的形象与图2中旧木椅的外观，参考视频1中的涂胶与压紧手部动作。全片采用平实自然的生活记录风格。

【情节概要】
1. 木工检查松动的椅背接缝。
2. 木工按视频1的手法涂抹木胶并把椅背压回原位固定。
3. 木工松开双手，椅背保持稳固。

【音频风格】
只保留木材摩擦与工具轻响等现场声，人物自然闭口。
```

### 整图入片

用户要整幅图片当作画面进入成片时，把下面这些写进对应段落：

- 图片的位置落进【核心任务】：起始画面、过程中的关键画面还是收尾画面；有多张就写清先后顺序。
- 图片与相邻内容怎么接，随【情节概要】对应节点写明：是连续承接，还是在图片前后生成新内容。
- 图片里要留住的主体、状态与空间关系，随对应情节节点写明；图片前后的动作与环境变化保持自然连贯。
- 多宫格图片按阅读顺序逐格说清画面内容，指代主体时统一用整图编号。

### 视频区间入片

用户要完整视频或指定区间进入成片时，把下面这些写进对应段落：

- 区间的位置落进【核心任务】：成片首段、中段还是尾段。
- 首段视频往后怎么接、尾段视频往前怎么衔、中段视频前后怎么连，随【情节概要】对应节点写明。
- 区间内容照实际呈现的人物、动作、事件与声音如实概括进【情节概要】；里面的语言语音按说话人、语言和逐字原文写明。
- 区间与生成内容之间，主体、空间与声音关系保持连续。

### 音频入片

用户要完整用上音频时，把下面这些写进对应段落：

- 使用范围落进【核心任务】：贯穿全片，还是只占成片某个局部连续区间及其位置。
- 音频承载的人声、音乐、环境音、音效写进【音频风格】；其中能确认的语言内容，按说话人和逐字原文写进【情节概要】对应节点。
- 音频与画面事件的对应关系，随对应情节节点写明。

### 台词与音色

- 用户给的台词、旁白、歌词逐字留进【情节概要】对应节点，并写清说话人与语言。
- 音色参考在【核心任务】里声明"<角色>的音色参考音频N"，并在【情节概要】的说话节点写明"使用音频N的音色说：'逐字原文'"。
- 无对白任务写清人物自然闭口、声音从哪来、保留哪些环境声。
- 用户明确要画面显示字幕时，写清字幕内容与出现位置；没提字幕就不写。

## 交付约定

- 输出语言跟着用户的主要指令走：主指令是中文就出中文，是英文就出英文；引号里的台词、歌词与画面文字保持原文。
- 整条回复就是整理后的请求正文，直接以【核心任务】段落开头；确需提示素材上限或个别限制时，在正文之后追加一行 `素材提示：` 或 `补充说明：`。
- 素材引用编号与用户原始请求保真一致，全程沿用同一套编号体系。
- 画幅与总时长只用于规划事件密度，始终以页面或接口参数的形式存在，不写进正文。
- 素材超过提交上限时，先给出完整请求，再追加一行 `素材提示：`；个别事实因素材读不到而只能照搬用户原文时，追加一行 `补充说明：`。正文本身要能直接拿去用。

## 交付前核对

给出成品前逐条对照：

- 人物身份与数量、事件因果、道具归属、空间关系、故事结局都与用户原文对得上。
- 成品经过模板结构化组织，每个事件、主体、台词都能在用户原文里找到出处。
- 每份真正用到的素材都有唯一且明确的职责与采用范围。
- 素材参考集中落在【核心任务】，音色参考写在对应的说话节点。
- 不同人物、道具、场景逐个绑定，一处只对应一个主体。
- 单人设定图只对应一个人物；多份素材共同界定同一主体时已明确声明。

- 画幅与总时长以规划参数的身份存在，正文里没有接口参数。
- 剧情重塑类、直接编辑类请求已被识别为越界，并说明了对应的处理方式。
- 成品以【核心任务】段落开头；【核心任务】【情节概要】齐全，【音频风格】【运镜与核心约束】按用户输入详略取舍。
- 【负面提示词】只在用户明确要求排除内容时出现，内容全部来自用户的排除项。
- 镜头时间戳按用户原文逐字带进【情节概要】；用户没写时间戳时各节点保持纯编号。
- 整条回复只有请求正文，直接以正文段落开始、也以正文段落结束。

## 运行环境适配

- **纯文本环境**：只处理用户文字与已写明的素材引用标签；对没读到的素材如实以待，不假称看过。
- **多模态环境**：在运行时允许的范围内读取图片、视频、音频，走"两遍看素材"并自动建映射。
- **无文件系统**：留住用户已有的素材编号与引用形式；对访问不到的素材，按"引用素材但当前不可得"的降级路子处理。
- **无网络**：对远程素材地址只保留引用形式，素材内容一律以用户文字为准。
- **仅输出文本**：本 Skill 只产出文本，文件写入、网络、工具调用、二进制输出等能力全部保持关闭。
